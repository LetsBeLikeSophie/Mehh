# Mehh 기획서 (SPEC)

- 앱 이름: **Mehh** (메흐)
- 스토어 표기: `Mehh: 사진 정리, 중복 사진 삭제` / `Mehh: Photo Cleaner & Duplicates`

> 이 문서는 Claude Code가 읽고 구현할 수 있도록 쓴 기획서다.
> 구현은 아래 "개발 단계" 순서대로 한 단계씩 진행하고, 단계마다 완료 기준을 확인한 뒤 다음으로 넘어간다.

---

## 1. 한 줄 소개

**귀찮아서 사진 정리를 못 하는 사람을 위한, 싸고 단순하고, "그날" 단위로 묶어주는 사진 정리 앱.**

## 2. 문제와 타깃

- 사진이 계속 쌓이지만 다시 보지는 않는다. 그래도 "아까워서" 못 지운다.
- 같은 사진이 두세 번 저장돼 있다. (카톡으로 받은 사진, 다시 저장한 사진 등)
- 비슷한 장소, 비슷한 시간, 비슷한 상황에서 여러 장 찍어서 고르기가 귀찮다.
- 타깃: 정리를 미루는 일반 스마트폰 사용자. 글로벌 출시 목표, 첫 출시는 한국어와 영어.

## 3. 제품 원칙

1. **기능은 최소한으로.** 새 기능은 "귀찮은 사람이 더 적게 손대게 만드는가?"로 판단한다.
2. **앱이 먼저 골라 두고, 사용자는 [추천 보기] 한 번으로 받은 뒤 예외만 고친다.** 하나하나 고르게 하지 않는다. (2026-10-22: 추천은 [추천 보기]를 눌러야 X로 들어간다. 틀릴 일이 거의 없는 것(실수 사진·완전히 같은 사본)만 처음부터 X — 5-2)
3. **바로 지우지 않는다.** 앱이 고른 것도 사용자가 [휴지통으로]를 눌러야 지워지고, 삭제는 항상 휴대폰 휴지통(30일 복구)을 거친다. (보류함은 2026-10-21 없앰: 애매한 사진은 표시 없이 두면 된다)
4. **사진은 폰 밖으로 나가지 않는다.** 모든 분석은 기기 안에서 한다. 서버 업로드 없음.
5. **싸고 부담 없게.** 주간 구독 없음. 평생 이용권 기본 + 1년 이용권 (9장).

## 4. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Flutter | 안드로이드 먼저 출시, 이후 iOS |
| 사진 접근·삭제 | `photo_manager` | 촬영 시각, 위치, 크기, 일괄 삭제 요청 |
| 로컬 DB | `drift` (SQLite) 또는 `isar` | 해시, 묶음, 사용자 결정 기록 |
| 이미지 해시 | Dart로 직접 구현 (dHash) + 원본 바이트 해시 | 1~2단계 |
| 흔들림·얼굴·눈 감음 | `google_mlkit_face_detection` + 라플라시안 분산(선명도) | 4단계 |
| 이미지 유사도 | `tflite_flutter` + 경량 임베딩 모델 (예: MobileNet 계열) | 4단계 |
| 장소 이름 | 플랫폼 지오코더 (`geocoding` 패키지) | 개인정보처리방침에 명시 |
| 결제 | `in_app_purchase` (소모성 상품) | 5단계 |
| 상태관리 | 기존에 쓰던 방식 그대로 (Riverpod 권장) | |

- 무거운 작업(해시 계산, 분석)은 `Isolate`에서 돌려 UI가 멈추지 않게 한다.
- 분석 결과는 DB에 저장하고, 새로 추가된 사진만 증분 분석한다.
- 패키지 버전과 API는 구현 시점의 최신 문서로 확인한다.

## 5. 화면 구성

### 디자인 원칙 (Notion 같은 미니멀 + 검정 포인트)

- 흰 바탕, 회색 면으로 구역을 나누고 테두리는 최소화. 선은 1px 연회색만.
- **검정은 포인트로만**, 화면당 1~2곳: 주요 버튼, 중요한 숫자 칩, 핵심 카드 1개, 지금 탭 밑줄.
- 색은 쓰지 않는다 (흰색·회색·검정만). 그림자 없음, 그라데이션 없음.
- 모서리: 카드 12px, 버튼 8px, 사진 썸네일 6px. 터치 영역 최소 44px.
- 폰트: IBM Plex Sans KR을 필요한 글자만 남겨 줄인 "Mehh Sans KR" (영문 포함, 약 3MB). 제목 700, 본문 400~500.

### 5-0. 용어 (모든 화면 공통)
| 말 | 뜻 |
|---|---|
| 킵 | 남기기로 결정 (이후 추천에서 빠짐) |
| 표시 없음 | 아직 정하지 않음. 앱이 다시 추천하지 않으니 애매하면 그대로 두면 된다 |
| 정리 줄 | 지울 후보. 아직 안 지움, 언제든 되돌릴 수 있음 (`toTrash`) |
| 휴지통으로 | 휴대폰 휴지통으로 실제로 보냄. **OS 휴지통으로 가는 버튼은 항상 이 말을 쓴다** |

### 5-1. 홈 (묶음 목록)
- 상단: 염소 로고, **Pro 칩**("무료 3개" 또는 "Pro", 누르면 Pro 안내), 설정
- 큰 글씨: "정리할 묶음 N개 남았어요" (남은 게 없을 때 분석 중이면 "사진을 살펴보고 있어요", 다 본 뒤에만 "지금은 정리할 묶음이 없어요") (2026-10-21, "정리할 날"이 헷갈려서 변경). 다 고른 묶음은 목록에 남고 "다 봤어요"로 흐리게 표시, 그날 새 사진이 생기면 다시 정리할 묶음이 된다, 아래에 "이번 달 휴지통으로 X GB 보냈어요" 또는 분석·장소 확인 진행률 (2026-10-21: 휴지통 사진은 30일 동안 용량을 그대로 차지하므로 "비웠어요"라고 하지 않는다. 휴지통으로 보낼 때 "휴지통을 비우면 공간이 생겨요"를 같이 알린다)
- **중복 사진 카드**: 작은 글씨 "무료로 정리" + "똑같은 사진 N장 찾았어요" + [살펴보기]. 분석 중에는 같은 자리에 흐린 한 줄 "똑같은 사진은 다 살펴본 뒤 알려 드려요 · 무료" → 정리 화면. N은 아직 고르지 않은 사본 수, 0이면 숨김
- **그날의 묶음 목록**: 대표 썸네일, "10월 3일 · 롯데월드", "214장 · 정리 추천 138장" — 전체 장수와 **앱이 고른 추천 장수만** (사용자가 직접 친 X는 세지 않는다, 2026-10-22). X를 쳐 두고 아직 안 보낸 묶음은 줄 끝에 작은 검은 점 (2026-10-22 Sophie R4-A). 최신순. **연도 구분선**("2025 ───")을 두고, 연도가 2개 이상이면 오른쪽 **연도 레일**: 투명 스크롤바처럼 누르거나 끌면 손가락 위치대로 목록이 따라 움직인다 (2026-10-22). 세로 점선 위에 연도 글자가 목록에서 그 연도가 시작하는 위치에 놓이고, 검은 손잡이가 지금 위치와 연도를 보여 준다. 목록 제목은 연도 없이 "10월 3일" (연도 구분선이 대신 보여 줌, 묶음 화면 제목은 올해가 아니면 연도까지). 위쪽 로고·Pro·설정 줄은 레일 여백 없이 오른쪽 끝에 붙인다
- 최근 앱에서 다시 열었을 때 마지막으로 불러온 지 10분(`reloadLibraryAfter`)이 지났으면, 지금 목록을 보여 준 채로 뒤에서 사진을 새로 불러온다 (UX 리뷰 2026-10-22)
- **따로 보기**: "낱장 사진"(사진이 1장뿐인 날을 모음), "캡처"(모든 캡처) → 정리 화면. 캡처 줄 아래 글자는 캡처 추천 장수("81장 · 정리 추천 70장", 없으면 "지울 캡처를 골라 보세요"). 홈 큰 숫자 "정리할 묶음 N개"에는 캡처를 세지 않는다 (시니어 리뷰 2026-10-23 S-3, 셀지는 Sophie 질문). 캡처 추천이 남아 있으면 "다 봤어요"로 흐리게 하지 않는다 (UX 리뷰 2026-10-23)
- 하단 탭 없음 (보류함 탭은 2026-10-21에 없앰)

### 5-2. 정리 화면 (공통 그리드) — 2026-10-22 위쪽 단순화
- 묶음, 낱장 사진, 캡처, 똑같은 사진 모두 이 화면으로 들어온다. 사진을 결정하는 새 화면을 따로 만들지 않는다.
- 위에서부터: 돌아가기 → **제목 뒤에 장수**("캡처  81장", 2026-10-23 Sophie) → 그날의 묶음은 시간 범위 한 줄(분석 중이면 "· 살펴보는 중") → 버튼 한 줄 → 4열 그리드. 버튼 아래 설명 줄은 두지 않는다 (2026-10-23 Sophie: 설명 대신 누를 때 한 번 묻기).
- 버튼 한 줄: **[추천 보기 · N장]** (앱 추천이 있을 때. 잠긴 묶음이면 버튼 안에 **자물쇠**) … 오른쪽 **[전체 선택]**/[선택 해제] (모두 X / **모두 표시 없음**, 추천은 지워지지 않아 [추천 보기]로 다시 받는다).
- **처음부터 X (2026-10-22 Sophie R1-C):** 틀릴 일이 거의 없는 것만 [추천 보기] 없이 처음부터 X로 보인다 — 낱장 사진의 "실수"(까맣거나 주머니 속), 똑같은 사진 중 남길 사진과 그림 해시·크기가 완전히 같은 사본. 결정으로 저장하지 않고 보이기만 하며, X를 끄면 킵으로 저장. "지난번에 X를 친 사진" 안내는 사용자가 직접 친 X만 센다.
- **앱 추천은 [추천 보기]를 눌러야 X로 들어간다.** 그 전에는 X가 없다. 다시 누르면 추천대로 다시 X. 그날의 묶음은 누를 때 "무료 묶음을 쓸까요?" 확인 창(남은 개수를 여기서 미리 보여 줌)을 거쳐 이번 달 무료 묶음을 하나 쓰거나 Pro로 열고, 다 썼으면 Pro 안내 (9장). 쓴 뒤에 따로 알림은 띄우지 않는다 (2026-10-23 Sophie: 미리 한 번 알리면 충분).
- 이유 표시("비슷한 컷", "흔들림", "실수", "똑같은 사진", "오래됨", "연달아 찍음")는 **X가 쳐진 사진에만** 왼쪽 아래에 보인다 — "왜 X인지". "베스트"·"남길 사진"은 추천을 받은 뒤에만. 배지 글자는 큰 글씨 설정에서도 사진을 덮지 않게 묶는다 (2026-10-22 Sophie 피드백).
- 위쪽 버튼 줄은 자리가 모자라면 줄을 바꾼다(글자를 자르지 않는다).
- X 버튼을 누르면 정리 ↔ 킵. 사진을 누르면 크게 보기(5-3). 똑같은 사진은 **묶음마다 새 줄에서 시작**해 어떤 사진끼리 같은지 보인다.
- 아래 버튼 하나: **[N장 휴지통으로]** (X가 없으면 흐리게 "X를 친 사진이 없어요").
- **캡처 추천 (무료, 2026-10-22 Sophie C4-A)**: [추천 보기 · N장]으로 받는다. 연달아 찍은 비슷한 캡처(60초 안·그림 해시 비슷)는 마지막 한 장만 남기고 앞 장을 "연달아 찍음", 그 밖에 90일 넘은 캡처를 "오래됨"으로 추천 (`planScreenshots`, `oldScreenshot`). "연달아 찍음"은 다음의 남는 장(X·휴지통이 아닌 장)과 비교해 한 화면이 통째로 사라지지 않게 하고, 연달아 찍은 묶음을 전부 보내면 "장면이 하나도 안 남아요"를 묻는다 (시니어 리뷰 2026-10-23 S-7). 단, 마지막 장까지 90일 넘은 연속 묶음은 앱이 통째로 추천하므로 묻지 않는다 (UX 리뷰 2026-10-23).
- **캡처 + Cortex** (2026-10-23 Sophie): 캡처를 고르면(X) 아래 [N장 휴지통으로] **옆에 작은 [Cortex로] 버튼**(공유하기처럼). 누를 때마다 한 줄로 묻는다: "캡처 N장을 Cortex로 보내고 지울까요?" [취소]/[보내고 지우기] (설명 문단 없음, 보내기만 하는 선택지 없음 — UX 리뷰 2026-10-23 UX-43, 2026-10-23 Sophie C2: 매번). [보내고 지우기]면 고른 캡처를 한 번에 Cortex로 보낸다(분석은 Cortex가). **Cortex가 저장을 마쳤다고 알려 올 때만** 그 캡처들을 휴지통으로 옮기며 "N장을 Cortex로 보내고 휴지통으로 보냈어요 · 30일 안에 되살릴 수 있고, 휴지통을 비우면 공간이 생겨요" (2026-10-22 Sophie C2-A). 약속: Mehh는 공유 글(EXTRA_TEXT)로 `mehh://cortex-saved?ids=1,2,3`(보낸 순서의 사진 id)을 같이 보내고, Cortex는 저장을 마치면 `mehh://cortex-saved?count=N`을 연다(Mehh로 돌아옴). **다음 버전 Cortex는 `&ids=`로 저장한 사진 id를 돌려주고, Mehh는 그 사진만 휴지통으로 보낸 뒤 "Cortex가 저장하지 않은 M장은 X 그대로예요"** (2026-10-23 Sophie C1-B). ids가 없으면 장수 규칙(아래). 신호 없이 돌아오면 "Cortex에 저장됐다는 신호가 없어서 휴지통으로 보내지 않았어요 · X는 그대로예요. Cortex에서 저장된 걸 확인했다면 [N장 휴지통으로]를 누르면 돼요. 다시 보내면 Cortex에 한 번 더 저장돼요." (다음 할 일까지, UX 리뷰 2026-10-23 UX-41). 알려 온 장수(count)가 보낸 장수보다 적으면(없거나 0 포함) 아무것도 옮기지 않고 "Cortex가 N장만 저장했다고 알려 왔어요 · 휴지통으로 보내지 않았어요 · X는 그대로예요. 어떤 캡처가 저장됐는지 Cortex에서 확인해 주세요. 다시 보내면 Cortex에 한 번 더 저장돼요." (시니어 리뷰 2026-10-23 S-2, UX-41). **"저장"이 아니라 "받음"을 기다린다** (2026-10-23 Sophie: 보내면 끝): Cortex는 받자마자 파일을 자기 저장소에 복사하고 바로 `mehh://cortex-saved?ids=`(받은 사진 id)로 돌아온다. Mehh는 그 사진을 휴지통으로 보내고, AI 분석·저장은 그 뒤 Cortex가 혼자 한다(앱을 꺼도 계속, 실패하면 Cortex가 다시). 아래 문구의 "저장"은 "받음"으로 읽는다. 기다리는 동안 Mehh 버튼은 잠그지 않고, 늦게 온 신호도 "Cortex로 보냄" 표시가 남은 사진에 한해 받는다. **믿을 수 있게 두 장치** (2026-10-23 Sophie): ① 저장 신호가 오면 휴지통 확인 창(안드로이드)을 띄우기 전에 "✓ Cortex가 N장 받았어요 · 휴지통으로 보내요"를 먼저 보여 준다(1.2초). ② 보냈는데 저장 신호를 아직 못 받은 사진은 그리드 왼쪽 위에 "Cortex로 보냄" 표시가 남는다(앱을 다시 켜도, 기기 안 `cortex_sent` 표). 저장이 확인되면 표시를 지운다. Cortex가 여러 장 받기를 못 하면 그렇다고 알리고 아무것도 지우지 않는다. [N장 휴지통으로]로 그냥 지울 수도 있다. 일반 공유는 없다. 설치 안 된 경우 스토어 안내는 Cortex가 나오는 나라에서만(5단계).
- 연속 컷·중복 묶음마다 최소 1장은 남긴다(6-2, 6-4). 사용자가 전부 X를 치고 보내면 "N개 장면은 사진이 하나도 안 남아요"를 묻는다.

### 5-3. 크게 보기
- 정리 화면에서 사진을 누르면 연다. 사진 한 장을 크게, 두 손가락으로 확대(손을 떼면 원래 크기).
- 위에 **정리 줄**, 사진 아래에 같은 모양의 **킵 줄** (2026-10-22): 사진을 그쪽으로 끌수록 검게 채워지고, 눌러도 된다.
- 밀기: **위 = 언제나 정리(X), 아래 = 언제나 킵**, 그리고 다음 사진으로. 좌우 = 이전·다음 (끝에서 처음으로 이어짐). 처음 민 방향 한 축으로만 움직인다. 밀 때 가운데 글자는 "정리"/"킵". 설명 글은 두지 않는다.
- 잘못 정했으면 반대로 밀면 된다. **되돌리기 버튼은 없다** (2026-10-22). 위쪽에는 돌아가기만. 위치 숫자("3 / 214")는 두지 않는다.
- 맨 아래 **한 줄 사진 줄**(동영상 편집 타임라인처럼): 화면보다 많으면 끝없이 이어지며 돌고, 다 들어가면 실제 장수만. 지금 사진은 테두리, 정리는 흐리게 + X, 킵은 체크.
- 크게 보기에서 고른 것은 바로 그리드에 반영된다. 사진을 누르면 확대 보기(열어본 기록 남김).

### 5-5. 설정
- 맨 위 **"Mehh Pro"** 줄 (UX 리뷰 2026-10-22): "Pro를 쓰고 있어요" 또는 "무료 묶음 N개 남음". 누르면 Pro 안내(구매·[구매 복원]) — 새 폰에서 구매 복원을 설정에서도 찾을 수 있게.
- "사진과 기록은 이 폰에만 있어요" 안내, [모든 기록 지우기]. Cortex가 설치돼 있으면 온보딩 약속과 설정 개인정보 안내에 "Cortex로 직접 보낸 캡처는 Cortex에서 AI로 분석해요. 내가 고른 캡처만, 보낼 때만 넘어가요." (2026-10-22 Sophie C1-A)
- **[문의하기]** (2026-10-21): 메일 앱을 열고(제목 "Mehh 문의 (버전)"), 메일 앱이 없으면 주소를 복사. 사진·기록은 저절로 보내지 않는다. 주소는 `config/app_config.dart`의 `supportEmail`, 비어 있으면 줄을 숨긴다.
- 아래에 [개인정보처리방침] → https://itssophie.dev/mehh/privacy.html (`web/privacy.html`, 한국어·영어, 2026-10-22). 출시 전 전문가 검토 권장.
- 맨 아래 버전 글자를 **7번 누르면 추천 정확도** 화면 (숨은 화면, 6-8).

## 6. 핵심 로직

### 6-1. 그날의 묶음 (Day Group)
- 사진을 촬영 시각 순으로 정렬한다.
- 다음 중 하나면 **새 묶음**을 시작한다:
  - 직전 사진과 시간 간격이 **3시간 이상**
  - 두 사진 모두 위치가 있고 거리가 **2km 이상**
  - 날짜가 바뀌었고 간격이 1시간 이상
- 스크린샷은 별도로 뺀다 (경로/앨범 이름에 Screenshots 포함 등). **모든 캡처를 "캡처" 하나로** 모은다. (2026-10-20, 월 단위에서 변경)
- 사진이 1장뿐인 묶음은 목록에서 빼서 **"낱장 사진" 하나로** 모은다 (`minDayPhotos`).
- 묶음 이름: "M월 D일 · {장소}". 장소는 묶음 중심 좌표를 지오코딩해 가장 구체적인 이름(장소명 > 동 > 구) 사용. 위치가 없으면 "M월 D일".
- 상수는 설정 파일로 빼서 튜닝 가능하게 한다.

### 6-2. 완전 중복 (Exact Duplicate)
- 1차 후보: 파일 크기 + 가로세로 크기가 같은 사진
- 2차 확인: 원본 바이트 해시(MD5/SHA-1)가 같으면 완전 중복
- 재저장으로 압축만 달라진 경우: dHash(64bit) 해밍 거리 **≤ 2** 이고 가로세로 비율이 같으면 중복으로 본다
- 실제 구현(2026-10-20): 해시가 같아도 아래는 **파일 크기까지 같을 때만** 중복 — 같은 크기로 10분 안에 찍힌 사진(연속 촬영), 스크린샷, 글자 많은 사진(택시 내역처럼 화면 구성이 같은 것)
- 남길 사진: 해상도가 가장 크고, 같으면 가장 먼저 찍힌 것. 사용자가 그 사진을 정리 줄에 넣으면 다음 사진이 남길 사진이 된다 (묶음마다 최소 1장)
- 중복 정리는 **무료**

### 6-3. 비슷한 연속 컷 (Similar Burst) — 4단계
- 같은 묶음 안에서, 촬영 간격 **60초 이내**이고 이미지 유사도가 기준 이상이면 같은 연속 컷으로 묶는다
- 3단계까지는 dHash 해밍 거리 ≤ 10으로 대신한다
- 4단계에서 임베딩 코사인 유사도로 교체 (기준값은 실험으로 결정, 시작값 0.90)

### 6-4. 베스트 컷 점수 — 4단계
- 선명도(라플라시안 분산), 얼굴이 있으면 눈 뜸 확률, 노출(너무 어둡거나 밝지 않음)을 합산
- 연속 컷마다 최고점 1장을 베스트로, 나머지를 정리 추천으로. 베스트를 사용자가 정리 줄에 넣으면 남은 사진 중 베스트를 다시 고른다
- 그 순간의 유일한 사진은 흔들렸어도 추천하지 않는다. 까맣거나 주머니 속처럼 **실수로 찍힌 사진**만 한 장이어도 추천 (2026-10-19)

### 6-5. 사용자 결정
- 상태: `undecided`(표시 없음) / `keep` / `toTrash`(X, 정리 줄) / `trashed`. `hold`는 2026-10-21에 없앰 (예전에 저장된 값은 표시 없음으로 본다)
  - `toTrash`는 2026-10-20 추가: 정리 줄에 넣었지만 아직 휴지통에 보내지 않음. 언제든 되돌릴 수 있다
- `keep`으로 결정한 사진은 이후 추천 대상에서 빠진다
- 모든 결정은 로그로 남긴다 (취향 학습용, 6-7)

### 6-6. "다 봤어요" 기준 (2026-10-21)
- 모든 사진을 정할 필요 없다. **앱 추천(X)을 다 처리하면** 그 묶음은 "다 봤어요": 휴지통으로 보냈거나, X를 꺼서 남겼거나.
- 표시 없는 사진은 앱이 다시 추천하지 않는다. "나머지 N장 킵할까요?" 같은 질문은 하지 않는다.
- 홈 "정리할 묶음 N개" = 정리할 사진(추천 또는 X)이 남은 묶음 수. 앱이 찾은 게 없는 묶음은 세지 않는다.

### 6-7. 취향 학습 — 6단계
- 결정 로그에 사진 특징을 함께 저장: 종류(음식/사람/풍경/문서 등, ML Kit 이미지 라벨링), 얼굴 수, 연속 컷 크기, 선명도
- 처음엔 통계 방식: 종류별로 "연속 컷당 평균 몇 장 남기는지"를 계산해 추천 개수에 반영
- 묶음 3~5개를 정리하기 전에는 기본 규칙만 사용
- 추천 이유를 문장으로 보여준다: "음식 사진은 보통 1장만 남기셔서 이걸 골랐어요"
- 모든 학습 데이터는 기기 안에만 저장

### 6-8. 추천 정확도 재기 (2026-10-21)
- 유료 기능(정리 추천)이 돈 받을 만한지 재는 기준. 폰 안에만 남고 [모든 기록 지우기]로 지워진다.
- 정리 화면에서 [휴지통으로]를 누른 순간, 그 화면 사진마다 "앱이 추천했나 / 실제로 보냈나 / 표시(비슷한 컷·흔들림·실수·똑같은 사진·베스트)"를 남긴다 (`models/pick.dart`, `logic/pick_stats.dart`). 사용자에게 X로 보였던 추천([추천 보기]로 받은 것 + 처음부터 X였던 것)만 센다(시니어 리뷰 2026-10-23 S-1). 캡처 추천(C4)·낱장·똑같은 사진도 기록되므로, 숨은 화면은 전체 숫자 아래에 **종류별** 받아들인 비율을 따로 보여 준다. 결제 기준은 그날의 묶음 (S-4, P3-A).
- 숨은 화면이 보여 주는 것: **추천을 받아들인 비율**(추천 중 실제로 보낸 것), 앱이 놓쳐서 직접 고른 사진, 베스트를 남긴 비율, 이유별 비율.
- 목표: **그날의 묶음** 추천을 받아들인 비율 80% 이상이면 결제를 켠다 (2026-10-23 Sophie P3-A: 돈을 받는 건 그날의 묶음뿐이라 숨은 화면의 큰 숫자도 그날의 묶음만, 모든 종류 합계는 참고 줄). 낮은 이유(표시)부터 기준을 고친다.
- **취향 학습 작게 시작 (2026-10-22 Sophie L1-A):** 같은 기록으로, 한 이유(비슷한 컷·흔들림·실수)를 20장 넘게 봤는데 받아들인 비율이 50% 미만이면 그 이유로는 더 추천하지 않는다 (`mutedReasons`, `learnMinSamples`·`learnMinAcceptRate`). 숨은 화면에 "자주 되돌려서 당분간 추천하지 않는 이유"를 보여 준다. **최근 30일 기록만** 보므로 꺼진 이유도 30일 뒤에는 다시 추천해 본다(다시 자주 되돌리면 또 꺼짐), 이유가 새로 꺼지는 순간 "흔들린 사진은 자주 남기셔서 당분간 추천하지 않아요 · 30일 뒤에 다시 골라 볼게요"를 한 줄 알린다 (2026-10-23 Sophie L1-B, `learnWindow`). 받아들인 비율은 꺼 둔 이유도 포함한 원래 기록 그대로 센다(학습 때문에 숫자가 좋아 보이지 않게).

### 6-9. ♥(즐겨찾기) 사진 (UX 리뷰 2026-10-23)
- 다른 앨범으로 옮긴 캡처(안드로이드: 이름은 캡처인데 캡처 폴더 밖)도 캡처 추천에서 뺀다 (2026-10-23 Sophie L2-B). 기기 확인 필요: 갤럭시 갤러리에서 앨범으로 "이동"하면 경로가 바뀌는지.
- 갤러리에서 ♥를 눌러 둔 사진은 묶음·캡처·똑같은 사진 추천과 처음부터 X에서 모두 뺀다(킵처럼). 사용자가 직접 X를 치는 것은 그대로 된다.
- 기기 확인 필요: 갤럭시 갤러리의 ♥가 안드로이드 즐겨찾기(IS_FAVORITE)로 들어오는지.

- 잠긴 그날의 묶음의 [추천 보기 · N장](자물쇠)을 누르면 **"무료 묶음을 쓸까요?"** 확인 창: "이 묶음의 비슷한 컷·흔들림 추천 N장을 보려면 이번 달 무료 묶음 1개를 써요. 지금 M개 남았어요. 한 번 연 묶음은 계속 열려 있어요." [취소]/[무료 묶음 쓰기]. 쓰면 자물쇠가 사라지고 추천이 X로 들어간다. 무료를 다 썼으면 Pro 안내를 열되 첫 줄에 이유 "이번 달 무료 묶음을 다 썼어요 · 11월 1일에 3개가 다시 생겨요" (2026-10-23 Sophie: 버튼 아래 설명 줄 대신, UX-45).
- 잠긴 묶음을 추천 없이 직접 X로 정리해 한 번 [휴지통으로] 보내면, 그 묶음은 "다 봤어요" (보이지 않는 추천 때문에 할 일로 남지 않게, 2026-10-22 Sophie R3-A. 남은 사진 id를 기록 `Store.addSeen`).
- **실수 사진은 무료 (2026-10-23 Sophie P2-A):** 잠긴 묶음에서도 "실수"(까맣거나 주머니 속) 사진은 처음부터 X. 잠금(무료 묶음·Pro)은 비슷한 컷·흔들림·베스트 고르기에만 걸리고, [추천 보기 · N장]의 N은 그 장수. 실수 사진만 있는 묶음은 잠기지 않는다.
- 홈 줄에는 자물쇠를 두지 않는다 (2026-10-23 Sophie: 무엇이 잠긴 건지 헷갈려서 [추천 보기] 버튼으로 옮김).
- 추천이 0장인 묶음은 잠그지 않는다. 홈의 "정리 추천 N장"은 그대로 보인다.
- 무료 묶음을 다 썼으면 Pro 안내에 "지금 무료로: 캡처 추천 N장 보기 ›"(또는 똑같은 사진) 한 줄 — 사지 않아도 정리를 이어 가게 (2026-10-23 Sophie P1-A).
- Pro 안내의 무료 설명은 "그날의 묶음 추천을 매달 3개까지" + "캡처·낱장 사진·똑같은 사진 추천은 Pro 없이도 늘 무료예요" (UX 리뷰 2026-10-23 UX-37).
- 달이 바뀌어 무료 묶음이 다시 생기면(지난달에 하나라도 썼을 때) 앱을 켜거나 다시 열 때 홈이 "이번 달 무료 묶음 3개가 다시 생겼어요"를 한 번 알린다 (UX 리뷰 2026-10-23 UX-40).
- 홈 위쪽 칩: "무료 묶음 N개" 또는 "Pro". 누르면 Pro 안내.
- **정리를 끝낸 순간 안내**: 그날의 묶음에서 [휴지통으로]를 보낸 직후 "N장을 휴지통으로 보냈어요 · 30일 안에 되살릴 수 있고, 휴지통을 비우면 공간이 생겨요. 남은 묶음도 추천을 바로 볼까요?" (시트가 알림을 덮으니 이때는 알림을 띄우지 않고 시트 첫 줄에 넣는다) + Pro 안내. **무료 묶음을 다 쓴 사용자에게만**, 하루 한 번까지 (2026-10-22 Sophie F1-B).
- 상품 (가격은 스토어가 그 나라 통화로 보여 줌):

  | 상품 ID | 종류 | 한국 | 미국 |
  |---|---|---|---|
  | `mehh_pro_lifetime` | 평생 이용권 (한 번 구매, 기본·"추천") | ₩12,900 | $9.99 |
  | `mehh_pro_yearly` | 1년 이용권 (자동 갱신 구독) | ₩7,900 | $5.99 |

- 회원 가입 없음. 산 것은 스토어 **[구매 복원]**으로 다시 받는다 (폰 바꿈·재설치). 앱을 켤 때마다 조용히 복원해 1년 이용권이 끝났는지 확인하고, 끝나는 순간 한 번 알린다 (UX 리뷰 2026-10-22). Pro가 켜지는 순간(시트에서 결제, 결제 대기 뒤 완료, 새 폰 조용한 복원) 홈이 "Pro가 열렸어요"를 한 번 알린다 (UX 리뷰 2026-10-23 UX-36). **Pro일 때 [추천 보기]로 추천을 본 묶음은 끝난 뒤에도 계속 열려 있다** (사진 id를 기억, 2026-10-22 Sophie F3-A. 그날의 묶음은 Pro여도 [추천 보기] 때 늘 기록 — UX 리뷰 2026-10-23 UX-35). 평생권은 한 번 받으면 지우지 않는다.
- 상태(Pro 여부, 무료로 연 묶음, 이번 달 사용 수)는 Keystore 암호화 저장소에만 (`data/pro.dart`). 재설치하면 무료 3개가 다시 생기지만 가치가 작아 막지 않는다.
- Google Play 구매 서명을 앱 안 공개키로 확인 (`playPublicKey`, `data/billing.dart`). **키가 비어 있는 안드로이드 빌드는 결제 상품을 아예 보여 주지 않는다** (돈이 나갔는데 Pro를 못 받는 일을 막음). 확인에 실패한 구매는 스토어에 "전달 완료"를 알리지 않아 Play가 3일 뒤 자동 환불한다 (UX 리뷰 2026-10-22). 결제를 열려면 Play Console 라이선스 키를 넣는다.
- 안내 시트에 자동 갱신과 해지 방법을 적는다 (구독 고지).
- 웹 미리보기는 결제 흉내만 (돈이 나가지 않음).

## 10. 개인정보·법적 체크

- 사진, 해시, 결정 로그 모두 기기 안에만 저장. 서버 없음.
- 얼굴은 **감지만** 하고 누구인지 식별하지 않는다 (GDPR, 일리노이 BIPA 등 생체정보 규정 회피)
- 지오코딩 시 좌표가 OS/구글 서비스로 전달될 수 있음 → 개인정보처리방침에 명시
- 스토어 데이터 안전 섹션: "수집 데이터 없음"을 목표로 설계 (분석 SDK, 광고 SDK 넣지 않음)
- 출시 전 개인정보처리방침과 결제·환불 문구는 전문가 검토 권장

## 11. 개발 단계 (순서대로)

### 1단계: 사진 불러오기 + 그날의 묶음 목록
- 권한 요청, 전체 사진 메타데이터 로드, 6-1 규칙으로 묶음 생성, 홈 화면과 묶음 안 그리드 (추천 없이 그냥 그리드)
- **완료 기준**: 내 폰 사진 수천 장에서 묶음 목록이 몇 초 안에 뜨고, 묶음 이름에 날짜와 장소가 나온다. 스크롤이 끊기지 않는다.

### 2단계: 완전 중복 찾기
- 6-2 구현, 백그라운드 Isolate에서 해시 계산 + DB 캐시, 홈의 중복 카드, [하나만 남기기] → 휴지통 이동
- **완료 기준**: 같은 사진을 두 번 저장해두면 중복으로 잡히고, 한 번의 확인으로 나머지가 휴지통에 간다. 앱을 다시 켜도 재계산하지 않는다.

### 3단계: 하나씩 넘기기 + 보류함
- 카드 화면 제스처, 결정 상태 저장, 되돌리기, 보류함 화면, 유예기간 계산, 열람 기록, 로컬 알림
- 연속 컷 묶기는 dHash 임시 기준 사용
- **완료 기준**: 위/아래/좌우 제스처가 오작동 없이 동작하고, 보류한 사진이 보류함에 D-day와 함께 보인다.
- (2026-10-21 이후: 보류함은 없앴고, 하나씩 넘기기는 그리드 + 크게 보기로 바뀜 — 5-2, 5-3 참고)
- 여기까지가 **개인 사용 가능한 MVP**

### 4단계: 비슷한 사진 + 베스트 컷
- TFLite 임베딩, 6-3/6-4 구현, 묶음 안 추천 정리 화면 완성 ([추천대로 정리])
- **완료 기준**: 연속으로 찍은 사진들이 한 연속 컷으로 묶이고, 흔들린 사진이 베스트로 뽑히지 않는다.

### 5단계: Mehh Pro 결제
- 평생 이용권·1년 이용권·매달 무료 묶음·구매 복원 — 코드는 2026-10-21 (9장). 남은 것: Play Console 상품 등록과 공개키 입력 후 실제 결제 확인
- **완료 기준**: 테스트 트랙에서 구매→모든 묶음 추천 열림, 앱을 지웠다 깔고 [구매 복원]하면 다시 Pro.
- **출시 전 결제 체크리스트** (2026-10-22 Sophie F4-A, 위에서부터 모두 확인해야 결제를 켠다):
  - [ ] `playPublicKey`(Play Console 라이선스 키)를 넣은 빌드에서만 결제 상품이 보인다. 키가 빈 빌드는 "스토어에 연결할 수 없어요".
  - [ ] Play Console에 `mehh_pro_lifetime`(일회성), `mehh_pro_yearly`(구독) 등록, 가격 확인(₩12,900 / ₩7,900).
  - [ ] 내부 테스트 트랙에서: 평생권 구매 → 모든 묶음 열림 → 앱 삭제·재설치 → [구매 복원] → 다시 Pro.
  - [ ] 1년권 구매 → 해지(테스트 계정은 빨리 끝남) → 앱을 다시 켜면 "1년 이용권이 끝났어요" 한 번, 연 묶음은 계속 열림.
  - [ ] 확인에 실패한 구매는 전달 완료를 알리지 않아 3일 뒤 자동 환불되는지 (Play 주문 관리에서).
  - [ ] 결제 대기(pending) 뒤 앱을 껐다 켜도 결제가 끝나면 Pro가 되는지.
  - [ ] 개인정보처리방침·이용약관·환불 안내 주소가 스토어 등록 정보와 앱 안에서 열리는지.
  - [ ] 출시용 서명키 백업(`C:\Projects\key\mehh-upload.jks`, `android/key.properties`).

### 다국어 (2026-10-21 시작)
- 첫 출시는 **한국어 + 영어**. 폰 언어가 한국어면 한국어, 그 밖은 영어.
- 문구: `lib/l10n/app_ko.arb`(기준)·`app_en.arb` → `flutter gen-l10n`이 `L10n` 생성. 영어는 단수·복수 처리.
- 날짜·시간: intl `DateFormat`으로 언어별 형식 (10월 3일 / Oct 3, 오후 1:12 / 1:12 PM).
- 폰트: Mehh Sans KR이 한글(자주 쓰는 2,350자)·영문을 맡고, 그 밖의 한글과, 다른 문자(일본어·중국어·태국어 등)는 휴대폰 기본 폰트로 자동 대체된다. 언어를 늘릴 때 화면에서 확인.

- 아직 남은 것: 스토어 소개·스크린샷·개인정보처리방침 영어판, iOS 사진 권한 안내 문구 영어판(InfoPlist.strings), 오른쪽→왼쪽 언어는 추가할 때 화면 점검.
