# Mehh 기획서 (SPEC)

- 앱 이름: **Mehh** (메흐)
- 스토어 표기: `Mehh: 사진 정리, 중복 사진 삭제` / `Mehh: Photo Cleaner & Duplicates`

> 이 문서는 Claude Code가 읽고 구현할 수 있도록 쓴 기획서다.
> 구현은 아래 "개발 단계" 순서대로 한 단계씩 진행하고, 단계마다 완료 기준을 확인한 뒤 다음으로 넘어간다.

---

## 1. 한 줄 소개

**귀찮아서 사진 정리를 못 하는 사람을 위한, 싸고 단순하고, "그날" 단위로 묶어주는 사진 정리 앱.**

## 2. 문제와 타깃

- 사진이 계속 쌓이지만 다시 보지는 않는다. 그래도 "아까워서" 못 지운다.
- 같은 사진이 두세 번 저장돼 있다. (카톡으로 받은 사진, 다시 저장한 사진 등)
- 비슷한 장소, 비슷한 시간, 비슷한 상황에서 여러 장 찍어서 고르기가 귀찮다.
- 타깃: 정리를 미루는 일반 스마트폰 사용자. 글로벌 출시 목표, 첫 출시는 한국어와 영어.

## 3. 제품 원칙

1. **기능은 최소한으로.** 새 기능은 "귀찮은 사람이 더 적게 손대게 만드는가?"로 판단한다.
2. **앱이 먼저 골라 두고, 사용자는 [추천 보기] 한 번으로 받은 뒤 예외만 고친다.** 하나하나 고르게 하지 않는다. (2026-10-22: 추천은 [추천 보기]를 눌러야 X로 들어간다. 틀릴 일이 거의 없는 것(실수 사진·완전히 같은 사본)만 처음부터 X — 5-2)
3. **바로 지우지 않는다.** 앱이 고른 것도 사용자가 [휴지통으로]를 눌러야 지워지고, 삭제는 항상 휴대폰 휴지통(30일 복구)을 거친다. (보류함은 2026-10-21 없앰: 애매한 사진은 표시 없이 두면 된다)
4. **사진은 폰 밖으로 나가지 않는다.** 모든 분석은 기기 안에서 한다. 서버 업로드 없음.
5. **싸고 부담 없게.** 주간 구독 없음. 평생 이용권 하나 (9장, 1년 이용권은 2026-10-29 Sophie B1-B로 판매 안 함).

## 4. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Flutter | 안드로이드 먼저 출시, 이후 iOS |
| 사진 접근·삭제 | `photo_manager` | 촬영 시각, 위치, 크기, 일괄 삭제 요청 |
| 로컬 DB | `drift` (SQLite) 또는 `isar` | 해시, 묶음, 사용자 결정 기록 |
| 이미지 해시 | Dart로 직접 구현 (dHash) + 원본 바이트 해시 | 1~2단계 |
| 흔들림·얼굴·눈 감음 | `google_mlkit_face_detection` + 라플라시안 분산(선명도) | 4단계 |
| 이미지 유사도 | `tflite_flutter` + 경량 임베딩 모델 (예: MobileNet 계열) | 4단계 |
| 장소 이름 | 플랫폼 지오코더 (`geocoding` 패키지) | 개인정보처리방침에 명시 |
| 결제 | `in_app_purchase` (소모성 상품) | 5단계 |
| 상태관리 | 기존에 쓰던 방식 그대로 (Riverpod 권장) | |

- 무거운 작업(해시 계산, 분석)은 `Isolate`에서 돌려 UI가 멈추지 않게 한다.
- 분석 결과는 DB에 저장하고, 새로 추가된 사진만 증분 분석한다.
- 패키지 버전과 API는 구현 시점의 최신 문서로 확인한다.

### 5-1. 홈 (묶음 목록)
- 상단: 염소 로고, **Pro 칩**("무료 3개" 또는 "Pro", 누르면 Pro 안내), 설정
- 큰 글씨: "정리할 묶음 N개 남았어요" (남은 게 없을 때 분석 중이면 "사진을 살펴보고 있어요", 다 본 뒤에만 "지금은 정리할 묶음이 없어요". 살펴보는 동안 캡처 추천이 있으면 진행률 아래에 "캡처 N장은 지금 바로 정리할 수 있어요 ›" → 캡처 화면, 2026-10-26 Sophie H1-A) (2026-10-21, "정리할 날"이 헷갈려서 변경). 다 고른 묶음은 목록에 남고 "다 봤어요"로 흐리게 표시, 그날 새 사진이 생기면 다시 정리할 묶음이 된다, 아래에 "이번 달 휴지통으로 X GB 보냈어요" 또는 분석·장소 확인 진행률 (2026-10-21: 휴지통 사진은 30일 동안 용량을 그대로 차지하므로 "비웠어요"라고 하지 않는다. 휴지통으로 보낼 때 "휴지통을 비우면 공간이 생겨요"를 같이 알린다)
- **용량 막대** (2026-10-24 Sophie): 홈과 정리 화면(모든 종류)이 **같은 막대·같은 뜻**. 막대 전체 = 사진·동영상 전체 용량 + 이번 달 휴지통으로 보낸 용량(동영상 포함, 2026-10-26 Sophie V2-A). 왼쪽부터 **검정** 사진·동영상(남는 것) · **연한 코랄** 추천 정리(앱 추천 + 선택해 둔 것: 그날의 묶음·낱장·캡처·똑같은 사진) · **코랄** 선택(**정리 화면에서만, 이 묶음에서 지금 선택한 것**, "처음부터 X" 포함) · **회색** 휴지통(이번 달 보낸 것). 홈에는 선택 칸이 없다(2026-10-24 Sophie). 묶음 안에서 선택하면 연한 코랄이 코랄로, 보내면 휴지통으로 옮겨 간다. 0이 아니면 최소 3px. 얇게(4px). 아래 한 줄: 글자 색 = 칸 색 "사진·동영상 2.2GB · 추천 정리 1.4GB" + 오른쪽 끝 "휴지통 34MB". 묶음 안에서는 "추천 정리 65MB / 116MB"(앞 숫자 = 선택, 코랄). **추천 정리는 선택해도 줄지 않는다**: 선택(코랄)은 추천 정리(연한 코랄) 칸 안의 일부로 그린다(2026-10-24 Sophie). 길면 줄을 바꾸지 않고 글자를 줄인다. 홈 묶음 줄 끝 점은 **추천 정리가 남은 묶음**에 연한 코랄(막대의 추천 정리와 같은 색·뜻). 선택해 두고 안 보낸 표시는 홈에 두지 않는다(2026-10-24 Sophie: 너무 많다). 사진·동영상 전체 용량은 기기(MediaStore Images+Video SIZE 합, 휴지통 제외)에 묻는다. 선택해 둔 큰 동영상은 추천 정리에 든다. **같은 높이**: 맨 위 줄(64)과 제목 칸(최소 112, 내용은 아래)을 같이 쓴다(`MehhHeader`). 휴지통으로 보낸 직후 알림에는 장수와 용량: "✓ N장 · M MB 휴지통으로 보냈어요 · …". 화면 문구에 "X를 친·쳐 둔"은 쓰지 않는다(예: "정리할 사진이 없어요").
- **당겨서 새로 고침** (2026-10-24 Sophie): **홈에서만** 아래로 당기면 갤러리와 다시 맞춘다(새로 찍은 사진, 갤러리에서 지우거나 되살린 사진). 되살린 사진은 앱의 "휴지통으로 보냄" 기억을 지워 다시 보인다.

- **그날의 묶음 목록**: 대표 썸네일, "10월 3일 · 롯데월드", "214장 · 추천 정리 138장" — 전체 장수와 **앱이 고른 추천 장수만** (사용자가 직접 친 X는 세지 않는다, 2026-10-22). X를 쳐 두고 아직 안 보낸 묶음은 줄 끝에 작은 검은 점 (2026-10-22 Sophie R4-A). 최신순. **연도 구분선**("2025 ───")을 두고, 연도가 2개 이상이면 오른쪽 **연도 레일**: 투명 스크롤바처럼 누르거나 끌면 손가락 위치대로 목록이 따라 움직인다 (2026-10-22). 세로 점선 위에 연도 글자가 목록에서 그 연도가 시작하는 위치에 놓이고, 검은 손잡이가 지금 위치와 연도를 보여 준다. 목록 제목은 연도 없이 "10월 3일" (연도 구분선이 대신 보여 줌, 묶음 화면 제목은 올해가 아니면 연도까지). 위쪽 로고·Pro·설정 줄은 레일 여백 없이 오른쪽 끝에 붙인다
- 최근 앱에서 다시 열었을 때 마지막으로 불러온 지 10분(`reloadLibraryAfter`)이 지났으면, 지금 목록을 보여 준 채로 뒤에서 사진을 새로 불러온다 (UX 리뷰 2026-10-22). 접근 범위가 바뀌거나 기록을 지운 뒤 다시 읽을 때도 같은 길로, 목록을 보여 준 채 읽는다. 다시 읽기는 한 번에 하나만 돌고(도는 중 또 읽으라면 끝난 뒤 한 번 더), 읽는 사이 휴지통으로 보낸 사진은 다 읽은 뒤에도 빠져 있다. 장소 채우기도 한 번에 하나만, 캐시 파일 쓰기는 줄 세운다 (리뷰 2026-10-30 S-2)
- **따로 보기**: "낱장 사진"(사진이 1장뿐인 날을 모음), "캡처"(모든 캡처) → 정리 화면. 캡처 줄 아래 글자는 캡처 추천 장수("81장 · 추천 정리 70장", 없으면 "지울 캡처를 골라 보세요"). 홈 큰 숫자 "정리할 묶음 N개"에는 캡처를 세지 않는다 (시니어 리뷰 2026-10-23 S-3, 셀지는 Sophie 질문). 캡처 추천이 남아 있으면 "다 봤어요"로 흐리게 하지 않는다 (UX 리뷰 2026-10-23)
- 하단 탭 없음 (보류함 탭은 2026-10-21에 없앰)

### 5-2. 정리 화면 (공통 그리드) — 2026-10-22 위쪽 단순화
- 묶음, 낱장 사진, 캡처, 똑같은 사진 모두 이 화면으로 들어온다. 사진을 결정하는 새 화면을 따로 만들지 않는다.
- 위에서부터: 돌아가기 → **제목 뒤에 장수**("캡처  81장", 2026-10-23 Sophie) → 그날의 묶음은 시간 범위 한 줄(분석 중이면 "· 살펴보는 중") → 버튼 한 줄 → 4열 그리드. 버튼 아래 설명 줄은 두지 않는다 (2026-10-23 Sophie: 설명 대신 누를 때 한 번 묻기).
- 버튼 한 줄: **[추천 보기 · N장]** (앱 추천이 있을 때. 잠긴 묶음이면 버튼 안에 **자물쇠**) … 오른쪽 **[전체 선택]**/[선택 해제] (모두 X / **모두 표시 없음**, 추천은 지워지지 않아 [추천 보기]로 다시 받는다).
- **처음부터 X (2026-10-22 Sophie R1-C):** 틀릴 일이 거의 없는 것만 [추천 보기] 없이 처음부터 X로 보인다 — 낱장 사진·그날의 묶음의 "실수"(까맣거나 주머니 속), 똑같은 사진 중 남길 사진과 그림 해시·크기가 완전히 같은 사본. 결정으로 저장하지 않고 보이기만 하며, X를 끄면 킵으로 저장.
- **[추천 보기 · N장]의 N은 누르면 X가 되는 장수**(잠긴 추천 + 이미 X로 보이는 실수 사진, 2026-10-24 버그: 66장이라 해 놓고 78장). 코인 확인 창의 "추천 N장"도 같은 수.
- **끌어서 여러 장 선택** (2026-10-24 Sophie): 그리드에서 사진 위를 **옆으로** 끌기 시작하면 지나가는 사진을 한꺼번에 선택한다. 첫 사진이 선택돼 있었으면 반대로 푼다(X 버튼과 같은 결과). 위아래로 끌면 그대로 스크롤. 빨리 끌어 건너뛴 사진도 화면 순서대로 채운다.
- **가장자리에서 밀면 뒤로** (2026-10-24 Sophie): 정리 화면에서 화면 왼쪽·오른쪽 끝(28px) 안에서 시작한 옆 끌기는 사진 선택 대신 뒤로 간다(60px 넘게 또는 빠르게). 캡처처럼 사진이 화면을 꽉 채워도 뒤로 갈 수 있게.
- **열어 둔 정리 화면도 지금 사진첩을 본다** (UX-70, 2026-10-27): 정리·크게 보기 화면은 그릴 때마다 지금 사진첩에서 같은 묶음을 다시 찾는다(같은 종류에서 그날의 묶음은 같은 id, 아니면 사진이 가장 많이 겹치는 것). 화면을 연 채 나가 새 캡처를 찍고 돌아와도(10분 넘으면 다시 불러옴) 새 칸과 장수가 보인다. 사진 구성이 같아도 늘 사진첩의 묶음을 쓴다: 갤러리에서 누른 ♥·다른 앨범으로 옮김도 돌아오면 바로 반영돼 추천에서 빠진다(시니어 리뷰 2026-10-28 S-1). 열려 있는 그날의 묶음이 다시 묶여(첫 장소 확인 등) 갈라져도 보던 사진은 화면에 그대로 남는다(지운 사진은 빠지고 새 사진은 붙음). 다시 열면 갈린 묶음으로 보인다(UX-75).
- **큰 동영상** (2026-10-24 Sophie): 홈 "따로 보기"에 [큰 동영상] 줄("N개 · 2.3GB"). 50MB 이상(`bigVideoBytes`, ♥ 제외)을 용량 큰 순으로, 칸마다 "2:05 · 900MB". 앱이 골라 주지 않는다(추천 없음, Cortex 없음). 선택 → [N개 휴지통으로]는 같은 흐름(동영상은 제목·버튼·확인 창·알림 모두 "개"로 센다, 홈 줄과 같은 단위). 크게 보기에서는 첫 장면 아래에 "12:40 · 1.4GB · 10월 3일"(UX-49), 가운데 ▶를 누르면 그 영상을 갤러리(기본 동영상 앱)에서 연다(앱 안 재생기는 없음, 열 앱이 없으면 한 줄 안내, 2026-10-26 Sophie V3-A). 동영상은 크기·길이·날짜만 읽고 분석하지 않는다(그날의 묶음·중복에 안 들어감, 용량 막대에는 들어감 V2-A). 크기는 기기에 한 번에 묻는다(MediaStore Video SIZE). 권한 READ_MEDIA_VIDEO 추가.
- **묶음 이름 바꾸기** (2026-10-24 Sophie): 홈 묶음 줄을 길게 누르거나 정리 화면 제목을 누르면 "묶음 이름" 창. 입력 칸 오른쪽 [원래 이름으로]가 기본 이름(날짜·장소)을 다시 넣는다. 비우거나 기본 이름이면 바꾼 이름을 지운다. 기기 안 `names` 표(묶음 id → 이름 + 그때의 사진 id). 첫 사진을 지워 묶음 id가 바뀌어도 사진이 겹치는 이름을 찾아 그대로 보인다(코인 열림과 같은 방식). 겹침으로 찾기는 그날의 묶음끼리만, 한 이름은 가장 많이 겹치는 한 묶음에만(낱장 사진으로 옮겨 간 사진이나 갈라진 다른 쪽은 기본 이름).
- **[추천 보기]는 켜고 끄는 버튼** (2026-10-24 Sophie): 버튼 모양·글자는 늘 [추천 보기 · N장] 그대로, **앞 칸만** 바뀐다: 잠김 = 자물쇠, 끔 = 빈 체크 칸, 켬 = 체크(2026-10-24 Sophie). 누르면 추천이 X로 들어간다(켬). 다시 누르면 추천으로 들어간 X만 풀린다(직접 선택한 사진과 실수 사진처럼 처음부터 X인 것은 그대로). 상태가 ✓로 보이므로 "X처럼 켜고 끄는 표시" 예외에 든다. 한 번 연 묶음은 다시 켜도 코인을 쓰지 않는다. 켜 두고 화면을 나갔다 와도 켜짐(✓)으로 보이고 한 번 누르면 꺼진다(UX-60). 추천 정확도 기록은 지금 X인 추천만 "보여 준 추천"으로 센다(그 사이 새로 생긴 추천은 빼다, UX-61).
- **앱 추천은 [추천 보기]를 눌러야 X로 들어간다.** 그 전에는 X가 없다. 다시 누르면 추천대로 다시 X. 그날의 묶음은 누를 때 "코인 1개로 열까요?" 확인 창(남은 개수를 여기서 미리 보여 줌)을 거쳐 이번 달 코인을 하나 쓰거나 Pro로 열고, 다 썼으면 Pro 안내 (9장). 쓴 뒤에 따로 알림은 띄우지 않는다 (2026-10-23 Sophie: 미리 한 번 알리면 충분).
- 이유 표시("비슷한 컷", "흔들림", "실수", "똑같은 사진", "오래됨", "연달아 찍음")는 **X가 쳐진 사진에만** 왼쪽 아래에 보인다 — "왜 X인지". "베스트"·"남길 사진"은 추천을 받은 뒤에만. 배지 글자는 큰 글씨 설정에서도 사진을 덮지 않게 묶는다 (2026-10-22 Sophie 피드백). 크게 보기의 이유 줄도 같은 규칙을 한 함수(`shownTag`)로 쓴다 (UX-86).
- 위쪽 버튼 줄은 자리가 모자라면 줄을 바꾼다(글자를 자르지 않는다).
- X 버튼을 누르면 정리 ↔ 킵. 사진을 누르면 크게 보기(5-3). 똑같은 사진은 **묶음마다 새 줄에서 시작**해 어떤 사진끼리 같은지 보인다.
- 아래 버튼 하나: **[N장 휴지통으로]** (X가 없으면 흐리게 "정리할 사진이 없어요").
- **캡처 추천 (무료, 2026-10-22 Sophie C4-A)**: [추천 보기 · N장]으로 받는다. 연달아 찍은 비슷한 캡처(60초 안·그림 해시 비슷)는 마지막 한 장만 남기고 앞 장을 "연달아 찍음", 그 밖에 90일 넘은 캡처를 "오래됨"으로 추천 (`planScreenshots`, `oldScreenshot`). "연달아 찍음"은 다음의 남는 장(X·휴지통이 아닌 장)과 비교해 한 화면이 통째로 사라지지 않게 하고, 연달아 찍은 묶음을 전부 보내면 "장면이 하나도 안 남아요"를 묻는다 (시니어 리뷰 2026-10-23 S-7). 단, 마지막 장까지 90일 넘은 연속 묶음은 앱이 통째로 추천하므로 묻지 않는다 (UX 리뷰 2026-10-23).
- 연속 컷·중복 묶음마다 최소 1장은 남긴다(6-2, 6-4). 사용자가 전부 X를 치고 보내면 "N개 장면은 사진이 하나도 안 남아요"를 묻는다.
- **Cortex로 보내기 — 모든 종류** (2026-10-24 Sophie): **보내는 사진은 직접 고른 것만**(X 버튼·끌어서·[전체 선택]). [추천 보기]로 X가 됐거나 실수 사진처럼 처음부터 X인 추천은 휴지통으로는 가도 Cortex로는 안 간다. 직접 고른 사진이 없으면 [Cortex로] 버튼도 없다 (2026-10-26 Sophie C1-B, 버릴 캡처 수천 장이 AI 앱으로 가지 않게). 화면을 나갔다 와도 같다: 지금 추천 목록에 있는 사진은 이 화면에서 손으로 고른 것만 보낸다(시니어 리뷰 2026-10-27 S-1). **전에 보낸 사진도 고르면 다시 보낸다**: Mehh는 Cortex에 그 사진이 지금 있는지 알 수 없어서(Cortex에서 지웠을 수 있다) 빼지 않고, 창에 "이미 Cortex로 보낸 N장도 다시 보내요" 한 줄 (2026-10-30 Sophie, 10-28 C3-B "받은 사진은 빼고 보내기"를 되돌림). Cortex가 설치돼 있고 직접 고른 사진이 있으면, 캡처·그날의 묶음·낱장·똑같은 사진 어디서나 아래 [N장 휴지통으로] 옆에 작은 [Cortex로] 버튼(늘 같은 자리).
  - **순서**: [Cortex로] → 매번 "N장을 Cortex로 보낼까요?" + 작은 한 줄 "Cortex에서 AI로 분석해요"(2026-10-24 Sophie), 고른 사진 중 이미 보낸 것("Cortex로 보냄")이 있으면 한 줄 더 "이미 Cortex로 보낸 N장도 다시 보내요"(보내는 범위는 그대로, UX-57) [취소]/[보내기] (UX 리뷰 2026-10-23 UX-43, Sophie C2: 매번) → Cortex가 받자마자 파일을 복사하고 돌아옴 → Mehh 창 "✓ Cortex가 N장 받았어요" + "분석은 Cortex가 뒤에서 해요. 앱을 닫아도 돼요. 이 사진을 휴지통으로 보낼까요?" (사진은 아직 폰에 있으니 "옮겼어요·지울까요"라고 하지 않는다, 시니어 리뷰 2026-10-24 S-6; 못 받은 게 있으면 "Cortex가 받지 못한 M장은 그대로 둬요.") [나중에]/[휴지통으로] → 안드로이드 휴지통 확인 창 → 일반 휴지통 알림 "✓ N장 · M MB 휴지통으로 보냈어요 …". [휴지통으로]는 [N장 휴지통으로]와 같은 뒤처리(정확도 기록·"다 봤어요"·Pro 안내, S-2).
  - **표시**: Cortex로 보낸 사진은 왼쪽 위 "Cortex로 보냄" 하나(받았다는 신호가 왔든 안 왔든, 앱을 다시 켜도 남는다, 기기 안 `cortex_sent` 표). Mehh가 보낸 기록일 뿐 Cortex에 지금 있는지 묻지 않으므로 "Cortex에 있음"이라고 하지 않는다 (2026-10-30 Sophie). 받았다는 신호(`cortex_sent.got`)는 어느 사진을 기다리는지 가리는 데만 쓴다. 휴지통으로 가면 표시를 지운다. 표시는 X 버튼 아래에 깔리고 누르기를 막지 않는다.
  - **기다리는 동안**: 버튼은 잠그지 않는다. 또 보내도 되고, 신호는 "아직 못 받은" 사진 기준으로만 맞춘다(묶음이 섞이지 않게, S-3). 늦게 온 신호도 받는다.
  - **안 받았을 때**: 신호 없이 돌아오면 "Cortex가 받았다는 신호가 없어서 휴지통으로 보내지 않았어요 · X는 그대로예요. Cortex에서 받은 걸 확인했다면 [N장 휴지통으로]를 누르면 돼요." 장수만 오는데 보낸 것보다 적으면 "Cortex가 N장만 받았다고 알려 왔어요 · 휴지통으로 보내지 않았어요 · X는 그대로예요." Cortex가 여러 장 받기를 못 하면 그렇다고 알리고 아무것도 하지 않는다.
  - 일반 공유는 없다. **Cortex가 없으면** 버튼은 그대로 보이고, 누르면 "Cortex가 필요해요" + "사진·캡처를 메모로 정리해 주는 앱이에요. 받은 뒤 다시 [Cortex로]를 눌러 주세요." [취소]/[받으러 가기] → Play 스토어 Cortex 페이지(`cortexStoreUrl`, 비우면 버튼 숨김) (2026-10-25 Sophie).

#### Cortex 약속 (두 앱 사이)

- Mehh는 ACTION_SEND_MULTIPLE로 사진을 보내며 공유 글(EXTRA_TEXT)에 `mehh://cortex-saved?ids=1,2,3`(보낸 순서의 사진 id)을 같이 넣는다.
- Cortex는 받자마자 파일을 자기 저장소에 복사하고(공유 권한은 임시), 끝나면 `mehh://cortex-saved?count=N&ids=…`(복사한 사진 id)를 열어 Mehh로 돌아온다. 신호의 뜻은 "저장 완료"가 아니라 **"받았음"**. AI 분석·저장은 그 뒤 Cortex가 혼자 한다(앱을 꺼도 계속, 실패하면 Cortex가 다시).
- `ids`가 있으면 그 사진만, 없으면(예전 Cortex) `count`가 마지막으로 보낸 장수 이상일 때만 묻는다.

### 5-3. 크게 보기
- 정리 화면에서 사진을 누르면 연다. 사진 한 장을 크게, 두 손가락으로 벌린 곳을 확대하고 손가락을 옮기면 확대한 곳이 따라간다(손을 떼면 원래 크기). 두 손가락 동작이라 한 손가락 밀기(정리·킵·넘기기)와 부딪히지 않는다 (2026-10-29 Sophie). 확대하다 한 손가락을 먼저 떼도, 손가락이 모두 떨어질 때까지 남은 손가락은 밀기로 읽지 않는다 (UX-85).
- 위에 **정리 줄**, 사진 아래에 같은 모양의 **킵 줄** (2026-10-22): 사진을 그쪽으로 끌수록 검게 채워지고, 눌러도 된다.
- 밀기: **위 = 언제나 정리(X), 아래 = 언제나 킵**, 그리고 다음 사진으로. 좌우 = 이전·다음 (끝에서 처음으로 이어짐). 처음 민 방향 한 축으로만 움직인다. 밀 때 가운데 글자는 "정리"/"킵". 설명 글은 두지 않는다.
- 잘못 정했으면 반대로 밀면 된다. **되돌리기 버튼은 없다** (2026-10-22). 위쪽에는 돌아가기만. 위치 숫자("3 / 214")는 두지 않는다.
- 맨 아래 **한 줄 사진 줄**(동영상 편집 타임라인처럼): 화면보다 많으면 끝없이 이어지며 돌고, 다 들어가면 실제 장수만. 지금 사진은 테두리, 정리는 흐리게 + X, 킵은 체크.
- 크게 보기에서 고른 것은 바로 그리드에 반영된다. 사진을 눌러도 따로 열리는 화면은 없다(같은 사진이 한 겹 더 열려 헷갈렸다, 2026-10-29 Sophie).
- **길게 누르기 = 정리 끝내기** (2026-10-24 Sophie: 화면에 버튼을 더 넣지 않는다, 정리 화면 그리드의 어디든·크게 보기 공용 `HoldToFinish`. 그리드에서는 보낸 뒤 그 묶음에서 나간다): **길게 누르기로 잡힌 뒤(0.5초)부터** 화면 가운데에 동그라미가 차오르고(0.6초, 그냥 누르기에는 안 보인다, 손가락에 가리지 않게 가운데), 다 차면 지금 선택한 사진 기준으로 묻는다: 제목 "N장 휴지통으로"(아래 버튼과 같은 말, 설명 문장 없음) [계속 보기]/[휴지통으로]. 다 차기 전에 떼거나, 누른 채 손가락이 조금이라도 움직이면(밀기·당기기) 바로 멈추고 아무 일도 없다(2026-10-24 버그: 아래로 끄는데 끝내기 창). 정리할 사진이 있으면 "N장을 휴지통으로 보내고 끝낼까요?" + "M장 중 N장을 선택했어요." [계속 보기]/[휴지통으로] → 정리 화면으로 돌아가 [N장 휴지통으로]와 똑같이 보낸다. 없으면 "정리할 사진이 없어요. 끝낼까요?" [계속 보기]/[끝내기]. 선택한 사진이 1장 이상일 때 3초 멈추면 가운데에 "길게 누르면 정리를 끝낼 수 있어요"가 3초 뜬다(그리드·크게 보기 합쳐 통틀어 5번까지, 길게 누르기를 한 번 쓰면 그 뒤로 안 띄움, 기기 안 `counters` 표, 2026-10-24 Sophie). 왼쪽 위 돌아가기는 그대로 둔다.

## 6. 핵심 로직

### 6-1. 그날의 묶음 (Day Group)
- 사진을 촬영 시각 순으로 정렬한다.
- 다음 중 하나면 **새 묶음**을 시작한다:
  - 직전 사진과 시간 간격이 **3시간 이상**
  - 두 사진 모두 위치가 있고 거리가 **2km 이상**
  - 날짜가 바뀌었고 간격이 1시간 이상
- 스크린샷은 별도로 뺀다 (경로/앨범 이름에 Screenshots 포함 등). **모든 캡처를 "캡처" 하나로** 모은다. (2026-10-20, 월 단위에서 변경)
- 사진이 1장뿐인 묶음은 목록에서 빼서 **"낱장 사진" 하나로** 모은다 (`minDayPhotos`).
- 묶음 이름: "M월 D일 · {장소}". 장소는 묶음 중심 좌표를 지오코딩해 가장 구체적인 이름(장소명 > 동 > 구) 사용. 위치가 없으면 "M월 D일".
- 상수는 설정 파일로 빼서 튜닝 가능하게 한다.

### 6-2. 완전 중복 (Exact Duplicate)
- 1차 후보: 파일 크기 + 가로세로 크기가 같은 사진
- 2차 확인: 원본 바이트 해시(MD5/SHA-1)가 같으면 완전 중복
- 재저장으로 압축만 달라진 경우: dHash(64bit) 해밍 거리 **≤ 2** 이고 가로세로 비율이 같으면 중복으로 본다
- 실제 구현(2026-10-20): 해시가 같아도 아래는 **파일 크기까지 같을 때만** 중복 — 같은 크기로 10분 안에 찍힌 사진(연속 촬영), 스크린샷, 글자 많은 사진(택시 내역처럼 화면 구성이 같은 것)
- 남길 사진: 해상도가 가장 크고, 같으면 가장 먼저 찍힌 것. 사용자가 그 사진을 정리 줄에 넣으면 다음 사진이 남길 사진이 된다 (묶음마다 최소 1장)
- 중복 정리는 **무료**

### 6-3. 비슷한 연속 컷 (Similar Burst) — 4단계
- 같은 묶음 안에서, 촬영 간격 **60초 이내**이고 이미지 유사도가 기준 이상이면 같은 연속 컷으로 묶는다
- 3단계까지는 dHash 해밍 거리 ≤ 10으로 대신한다
- 4단계에서 임베딩 코사인 유사도로 교체 (기준값은 실험으로 결정, 시작값 0.90)

### 6-4. 베스트 컷 점수 — 4단계
- 선명도(라플라시안 분산), 얼굴이 있으면 눈 뜸 확률, 노출(너무 어둡거나 밝지 않음)을 합산
- 연속 컷마다 최고점 1장을 베스트로, 나머지를 추천 정리으로. 베스트를 사용자가 정리 줄에 넣으면 남은 사진 중 베스트를 다시 고른다
- **눈 감은 컷 (폰 안 AI)** (2026-10-24 Sophie): 사진 분석이 끝나면 연속 컷(2장 이상)에 든 사진만 Google ML Kit 얼굴 감지(기기 안에서만)로 눈을 떴는지 본다(최근 묶음부터, 홈이 떠 있는 동안, 기기 안 `faces` 표에 사진마다 참·거짓만). 같은 순간에 눈 뜬 컷이 있으면 눈 감은 컷은 남길 후보에서 빠지고 "눈 감음"(크게 볼 때 "눈 감은 컷 · 같은 순간 눈 뜬 컷이 있어요")으로 추천한다. 모두 눈 감았으면 추천하지 않는다. 사람을 알아보지 않고 얼굴 정보는 남기지 않는다(처리방침 반영). 취향 학습 이유에도 들어간다. 앱이 약 13MB 커졌다.
- **베스트는 차이가 분명할 때만** (2026-10-24 Sophie): 1등과 2등 점수 차이가 `bestMargin`(0.3 ≈ 35% 더 선명) 이상일 때만 "베스트"라고 부른다. 애매하면 가장 나중 컷을 이름 없이 남기고 나머지는 "비슷한 컷". 베스트 이유도 눈에 띄는 차이만: 다른 컷보다 1.3배 이상 선명하면 "선명", 다른 컷 중 너무 어둡거나 밝은 게 있을 때만 "노출".
- **캡처 알아보기** (2026-10-24 Sophie): 폴더·파일 이름(screenshot·스크린샷·capture·캡처·smart select…)이나 휴대폰 화면 비율(긴 변 ≥ 짧은 변×2, 짧은 변 ≤ 1440)이면 캡처로 보고 그날의 묶음에서 뺀다(`looksLikeScreen`). 카톡으로 받은 화면 이미지도 캡처로 간다.
- 그 순간의 유일한 사진은 흔들렸어도 추천하지 않는다. 까맣거나 주머니 속처럼 **실수로 찍힌 사진**만 한 장이어도 추천 (2026-10-19)

### 6-5. 사용자 결정
- 상태: `undecided`(표시 없음) / `keep` / `toTrash`(X, 정리 줄) / `trashed`. `hold`는 2026-10-21에 없앰 (예전에 저장된 값은 표시 없음으로 본다)
  - `toTrash`는 2026-10-20 추가: 정리 줄에 넣었지만 아직 휴지통에 보내지 않음. 언제든 되돌릴 수 있다
- `keep`으로 결정한 사진은 이후 추천 대상에서 빠진다
- 모든 결정은 로그로 남긴다 (취향 학습용, 6-7)

### 6-6. "다 봤어요" 기준 (2026-10-21)
- 모든 사진을 정할 필요 없다. **앱 추천(X)을 다 처리하면** 그 묶음은 "다 봤어요": 휴지통으로 보냈거나, X를 꺼서 남겼거나.
- 표시 없는 사진은 앱이 다시 추천하지 않는다. "나머지 N장 킵할까요?" 같은 질문은 하지 않는다.
- 홈 "정리할 묶음 N개" = 정리할 사진(추천 또는 X)이 남은 묶음 수. 앱이 찾은 게 없는 묶음은 세지 않는다.

### 6-7. 취향 학습 — 6단계
- 결정 로그에 사진 특징을 함께 저장: 종류(음식/사람/풍경/문서 등, ML Kit 이미지 라벨링), 얼굴 수, 연속 컷 크기, 선명도
- 처음엔 통계 방식: 종류별로 "연속 컷당 평균 몇 장 남기는지"를 계산해 추천 개수에 반영
- 묶음 3~5개를 정리하기 전에는 기본 규칙만 사용
- 추천 이유를 문장으로 보여준다: "음식 사진은 보통 1장만 남기셔서 이걸 골랐어요"
- 모든 학습 데이터는 기기 안에만 저장

### 6-8. 추천 정확도 재기 (2026-10-21)
- 유료 기능(추천 정리)이 돈 받을 만한지 재는 기준. 폰 안에만 남고 [모든 기록 지우기]로 지워진다.
- 정리 화면에서 [휴지통으로]를 누른 순간, 그 화면 사진마다 "앱이 추천했나 / 실제로 보냈나 / 표시(비슷한 컷·흔들림·실수·똑같은 사진·베스트)"를 남긴다 (`models/pick.dart`, `logic/pick_stats.dart`). 사용자에게 X로 보였던 추천([추천 보기]로 받은 것 + 처음부터 X였던 것)만 센다(시니어 리뷰 2026-10-23 S-1). 캡처 추천(C4)·낱장·똑같은 사진도 기록되므로, 숨은 화면은 전체 숫자 아래에 **종류별** 받아들인 비율을 따로 보여 준다. 결제 기준은 그날의 묶음 (S-4, P3-A).
- 숨은 화면이 보여 주는 것: **추천을 받아들인 비율**(추천 중 실제로 보낸 것), 앱이 놓쳐서 직접 고른 사진, 베스트를 남긴 비율, 이유별 비율.
- 목표: **그날의 묶음** 추천을 받아들인 비율 80% 이상이면 결제를 켠다 (2026-10-23 Sophie P3-A: 돈을 받는 건 그날의 묶음뿐이라 숨은 화면의 큰 숫자도 그날의 묶음만, 모든 종류 합계는 참고 줄). 낮은 이유(표시)부터 기준을 고친다.
- **취향 학습 작게 시작 (2026-10-22 Sophie L1-A):** 같은 기록으로, 한 이유(비슷한 컷·흔들림·실수)를 20장 넘게 봤는데 받아들인 비율이 50% 미만이면 그 이유로는 더 추천하지 않는다 (`mutedReasons`, `learnMinSamples`·`learnMinAcceptRate`). 숨은 화면에 "자주 되돌려서 당분간 추천하지 않는 이유"를 보여 준다. **최근 30일 기록만** 보므로 꺼진 이유도 30일 뒤에는 다시 추천해 본다(다시 자주 되돌리면 또 꺼짐), 이유가 새로 꺼지는 순간 "흔들린 사진은 자주 남기셔서 당분간 추천하지 않아요 · 30일 뒤에 다시 골라 볼게요"를 한 줄 알린다 (2026-10-23 Sophie L1-B, `learnWindow`). 받아들인 비율은 꺼 둔 이유도 포함한 원래 기록 그대로 센다(학습 때문에 숫자가 좋아 보이지 않게).

### 6-9. ♥(즐겨찾기) 사진 (UX 리뷰 2026-10-23)
- 다른 앨범으로 옮긴 캡처(안드로이드: 이름은 캡처인데 캡처 폴더 밖)도 캡처 추천에서 뺀다 (2026-10-23 Sophie L2-B). 기기 확인 필요: 갤럭시 갤러리에서 앨범으로 "이동"하면 경로가 바뀌는지.
- 갤러리에서 ♥를 눌러 둔 사진은 묶음·캡처·똑같은 사진 추천과 처음부터 X에서 모두 뺀다(킵처럼). 사용자가 직접 X를 치는 것은 그대로 된다.
- 기기 확인 필요: 갤럭시 갤러리의 ♥가 안드로이드 즐겨찾기(IS_FAVORITE)로 들어오는지.

## 7. 삭제 정책

- 삭제는 항상 **시스템 휴지통**으로 보낸다 (안드로이드 11+는 휴지통 이동 요청 사용, 사용자 확인 창이 뜬다)
- 휴지통 이동이 실패하면 영구 삭제로 넘어가지 않고 실패를 알린다
- **안드로이드 11(API 30) 이상만 지원**한다 (minSdk 30, 2026-10-20 결정). 10 이하는 휴대폰 휴지통이 없어서 "바로 지우지 않는다"를 지킬 수 없기 때문
- 여러 장은 한 번의 요청으로 묶어서 보낸다 (확인 창을 여러 번 띄우지 않기)
- 삭제 후 확보한 용량을 누적 기록해 홈에 표시
- iOS는 "최근 삭제된 항목"으로 자동 이동

- 기기 확인 (2026-10-22, Sophie 갤럭시): Mehh가 휴지통으로 보낸 사진이 삼성 갤러리 앱의 휴지통에 보인다.

Pro·테스트 동안 무료면 코인을 쓰지 않으니 묻지 않고, 설정 스위치로만 켠다. 코인은 매달 1일(그 폰의 달 기준)에 3개로 다시 생기고 넘어가지 않는다. 허락하면 안드로이드 알림 허락 창 → 매달 1일 낮 12시쯤 한 번(정확한 시각 알람은 쓰지 않음, 폰을 다시 켜도 예약 유지 `RECEIVE_BOOT_COMPLETED`). 글: 코인을 쓰는 사람은 "이번 달 코인 3개가 다시 생겼어요 / 지난달 사진 묶음의 추천을 볼 수 있어요", Pro면 "지난달 사진 묶음이 기다려요 / 추천을 보고 한 번에 휴지통으로 보낼 수 있어요", 테스트 동안 무료면 Pro 안내와 같은 말 "비공개 테스트 동안은 모든 묶음 추천이 무료예요". 글은 앱을 켜거나 돌아올 때, Pro가 켜지거나 꺼질 때 지금 상태로 다시 맞춘다(Pro를 다 읽은 뒤에, 리뷰 2026-10-30 S-1). 묶음 개수는 알림 시점에 알 수 없어 넣지 않는다. 허락을 못 받으면 "폰 설정에서 Mehh 알림이 꺼져 있어요". 설정에 [매달 알림] 스위치(폰 설정에서 끄고 돌아오면 꺼짐으로 보임). 폰 안에서만 예약하고 밖으로 보내는 것은 없다. 물었다는 표시는 설정이라 [모든 기록 지우기]로 지우지 않는다(다시 묻지 않음).
- Google Play 사진·동영상 권한 정책 심사: "사진 정리가 앱의 핵심 기능"임을 설명

## 9. 수익 모델 — Mehh Pro (2026-10-21, 크레딧에서 변경)

크레딧(묶음마다 1개)은 뺐다. 리뷰: 사진이 많은 사람은 묶음이 수백 개라 너무 비싸고, 묶음마다 "쓸까?"를 정하는 게 "귀찮은 사람용"과 반대. 재설치·환불·위조 문제도 스토어 복원으로 풀린다.

| 기능 | 무료 | Pro |
|---|---|---|
| 묶음 보기, 똑같은 사진·낱장 사진·캡처 정리(추천 포함), 직접 X로 고르기, 크게 보기, Cortex로 보내기 | ✓ | ✓ |
| **그날의 묶음 추천 정리 보기** (X·베스트·이유 표시) | **매달 묶음 3개** | 모든 묶음 |

- 잠긴 그날의 묶음의 [추천 보기 · N장](자물쇠)을 누르면 **"코인 1개로 열까요?"** 확인 창: "추천 N장을 보려면 코인 1개를 써요. / M개 남음 · 한 번 열면 계속 열려 있어요." (2026-10-24 Sophie: 짧게) [취소]/[코인 쓰기]. 쓰면 자물쇠가 사라지고 추천이 X로 들어간다. 무료를 다 썼으면 Pro 안내를 열되 첫 줄에 이유 "이번 달 코인을 다 썼어요 · 11월 1일에 3개가 다시 생겨요" (2026-10-23 Sophie: 버튼 아래 설명 줄 대신, UX-45).
- 잠긴 묶음을 추천 없이 직접 X로 정리해 한 번 [휴지통으로] 보내면, 그 묶음은 "다 봤어요" (보이지 않는 추천 때문에 할 일로 남지 않게, 2026-10-22 Sophie R3-A. 남은 사진 id를 기록 `Store.addSeen`). 지금 추천이 모두 그때 본 사진일 때만 "다 봤어요": 잠긴 채 직접 정리한 묶음도 그 뒤 새로 찍은 사진에 추천이 생기면 다시 정리할 묶음(UX-81 2026-10-28).
- **실수 사진은 무료 (2026-10-23 Sophie P2-A):** 잠긴 묶음에서도 "실수"(까맣거나 주머니 속) 사진은 처음부터 X. 잠금(코인·Pro)은 비슷한 컷·흔들림·베스트 고르기에만 걸리고, [추천 보기 · N장]의 N은 그 장수. 실수 사진만 있는 묶음은 잠기지 않는다.
- 홈 줄에는 자물쇠를 두지 않는다 (2026-10-23 Sophie: 무엇이 잠긴 건지 헷갈려서 [추천 보기] 버튼으로 옮김).
- 추천이 0장인 묶음은 잠그지 않는다. 홈의 "추천 정리 N장"은 그대로 보인다.
- 코인을 다 썼으면 Pro 안내에 "지금 무료로: 캡처 추천 N장 보기 ›"(또는 똑같은 사진) 한 줄 — 사지 않아도 정리를 이어 가게 (2026-10-23 Sophie P1-A).

  | 상품 ID | 종류 | 한국 | 미국 |

  | `mehh_pro_lifetime` | 평생 이용권 (한 번 구매, 기본·"추천") | ₩12,900 | $9.99 |

- 안내 시트에 자동 갱신과 해지 방법을 적는다 (구독 고지).
- 웹 미리보기는 결제 흉내만 (돈이 나가지 않음).

## 10. 개인정보·법적 체크

- 사진, 해시, 결정 로그 모두 기기 안에만 저장. 서버 없음.
- 얼굴은 **감지만** 하고 누구인지 식별하지 않는다 (GDPR, 일리노이 BIPA 등 생체정보 규정 회피)
- 지오코딩 시 좌표가 OS/구글 서비스로 전달될 수 있음 → 개인정보처리방침에 명시
- 스토어 데이터 안전 섹션: "수집 데이터 없음"을 목표로 설계 (분석 SDK, 광고 SDK 넣지 않음)
- **이용약관·환불 안내**는 개인정보처리방침과 따로 한 페이지(`web/terms.html`, https://itssophie.dev/mehh/terms.html, 두 언어). 설정의 개인정보처리방침 아래와 Pro 안내의 "회원 가입 없음" 줄 아래에 밑줄 링크 "이용약관·환불" (2026-10-29 Sophie B3-B). 환불: 결제 후 48시간 안은 Google Play에서 직접, 그 뒤는 메일로(결제했는데 Pro가 안 켜짐·설명대로 동작 안 함은 환불).
- 출시 전 개인정보처리방침과 결제·환불 문구는 전문가 검토 권장

## 11. 개발 단계 (순서대로)

### 1단계: 사진 불러오기 + 그날의 묶음 목록
- 권한 요청, 전체 사진 메타데이터 로드, 6-1 규칙으로 묶음 생성, 홈 화면과 묶음 안 그리드 (추천 없이 그냥 그리드)
- **완료 기준**: 내 폰 사진 수천 장에서 묶음 목록이 몇 초 안에 뜨고, 묶음 이름에 날짜와 장소가 나온다. 스크롤이 끊기지 않는다.

### 2단계: 완전 중복 찾기
- 6-2 구현, 백그라운드 Isolate에서 해시 계산 + DB 캐시, 홈의 중복 카드, [하나만 남기기] → 휴지통 이동
- **완료 기준**: 같은 사진을 두 번 저장해두면 중복으로 잡히고, 한 번의 확인으로 나머지가 휴지통에 간다. 앱을 다시 켜도 재계산하지 않는다.

### 3단계: 하나씩 넘기기 + 보류함
- 카드 화면 제스처, 결정 상태 저장, 되돌리기, 보류함 화면, 유예기간 계산, 열람 기록, 로컬 알림
- 연속 컷 묶기는 dHash 임시 기준 사용
- **완료 기준**: 위/아래/좌우 제스처가 오작동 없이 동작하고, 보류한 사진이 보류함에 D-day와 함께 보인다.
- (2026-10-21 이후: 보류함은 없앴고, 하나씩 넘기기는 그리드 + 크게 보기로 바뀜 — 5-2, 5-3 참고)
- 여기까지가 **개인 사용 가능한 MVP**

### 4단계: 비슷한 사진 + 베스트 컷
- TFLite 임베딩, 6-3/6-4 구현, 묶음 안 추천 정리 화면 완성 ([추천대로 정리])
- **완료 기준**: 연속으로 찍은 사진들이 한 연속 컷으로 묶이고, 흔들린 사진이 베스트로 뽑히지 않는다.

### 5단계: Mehh Pro 결제
